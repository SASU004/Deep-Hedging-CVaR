# Security Policy

Security reports are welcomed and appreciated. If you believe you have found a security vulnerability in **QuantForge**, please report it responsibly.

## Supported Versions

- **Active development branch**: `main`
- Stage: **Stage 1 (frontend-only)** — no notebook execution or backend APIs are integrated.

## Reporting a Vulnerability

Please report suspected vulnerabilities to:

- `security@example.com`

Replace with a real contact before public production deployment.

When reporting, include:

- A clear description of the issue and potential impact
- Steps to reproduce (proof-of-concept if possible)
- Affected URLs/routes and environment details
- Any suggested remediation, if available

## Response Process

We aim to:

1. **Acknowledge** receipt of the report.
2. **Investigate** and validate the finding.
3. **Patch** confirmed issues with an appropriate fix.
4. **Coordinate disclosure** timelines when appropriate, especially for high-impact issues.

## Scope

In scope:

- Frontend application code
- Build configuration
- Deployment configuration and CI/CD workflows

## Out of Scope

Out of scope:

- Third-party services and dependencies (report upstream when applicable)
- Local development environments (developer machine configuration)
- User-modified or self-hosted deployments that differ from the repository defaults

## Responsible Disclosure

Please disclose vulnerabilities **privately** before public release. Avoid publishing proof-of-concept exploits or details that could put users at risk before a fix is available.
